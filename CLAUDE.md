# Demovid — CLI screen recorder for product demos (Linux / Sway / NVIDIA)

Screen Studio, but for Yousef's machine: record the whole output at OS level, then render auto-zoom on clicks/focus, an enlarged smoothed cursor, a webcam PiP, and loudness-normalised audio. CLI only, single user. Project page + working docs live in the vault: `~/sync/brain/root/projects/demovid/` (`repo` symlinks back here; `index.md` = public brief, `research.md` = tool/lib survey with verified facts, `roadmap.md` = milestones + open decisions, `board.md` = kanban). Read `research.md` before touching capture code — most of the hard constraints are there.

## Git: commit to `main`, never branch
Trunk-based like Console. No feature branches, no worktree branches that outlive the work — fold into `main` and delete. Ticket forks land on `main` too.

## Architecture (decided)
**Record raw + an event log; render afterwards.** Live effects are a dead end (bake decisions in, and the compositor gives a live client nothing to work with).

```
demovid rec      → ~/Videos/demovid/<ts>/{manifest.json, screen.mp4, cam.mp4, mic.flac, events.jsonl}
demovid render   → events → zoom plan (pure fn) → composite → NVENC mp4
demovid upload   → YouTube unlisted (Data API, resumable) → URL on the clipboard (wl-copy)
```
All artefacts share one monotonic start clock from `manifest.json`; every event and stream is `t`-relative to it. Never write raw video intermediates — `/home` sits at ~93 %; encode (NVENC) at capture time.

## Hard constraints of this machine (verified 2026-09-04, re-verify if the Sway build changes)
- **Sway 1.11 + wlroots 0.19.3 + pixman 0.46.4, built from tarballs in `~/src/` (installed 2026-09-04, live since the re-login that evening)**, launched by GDM autologin via `~/.local/bin/sway-nvidia` (`--unsupported-gpu`, `WLR_RENDERER=vulkan`, `WLR_RENDER_NO_EXPLICIT_SYNC=1`; `WLR_NO_HARDWARE_CURSORS` dropped 2026-09-05 so cursor tracking can work — backup at `~/.local/bin/sway-nvidia.bak-2026-09-05`) on a GTX 1060 (driver 580). `ext_image_copy_capture_manager_v1` and `ext_output_image_capture_source_manager_v1` are advertised (`uv run scripts/wl-globals.py image`), so the pointer-cursor session is testable for real. `libwlroots-0.18.so` and `~/src/sway-1.10.1/build` are kept for rollback (`sudo ~/.local/bin/meson install --no-rebuild -C ~/src/sway-1.10.1/build` — root's `/usr/bin/meson` 1.3.2 cannot read builds made by the pipx meson 1.11.2). "Log out and back in" on this box = `sudo systemctl restart gdm` (autologin re-fires; the Console hub survives because it runs as the system service `pm2-amar.service`).
- **Explicit sync broke screencopy on 1.11; fixed with `WLR_RENDER_NO_EXPLICIT_SYNC=1`** (2026-09-06). Symptom: `wf-recorder` (any version) and `grim` fail with "Failed to copy frame" / "failed to copy output", while sway accumulates leaked `anon_inode:sync_file` fds — Vulkan renderer + NVIDIA 580 explicit-sync fences. The env var is now set in `~/.local/bin/sway-nvidia` (confirm with `tr '\0' '\n' </proc/$(pgrep -x sway)/environ | grep WLR_`). NB the absolute fd count is NOT the signature: a healthy 1.11 session with the var set holds ~1750 `sync_file` fds steadily (measured 2026-09-06, grim fine). The leak shows as a count that keeps climbing between samples a minute apart plus the capture failures above.
- **This GPU can never use a hardware cursor, so wlroots is patched to report the software one** (2026-09-06). The NVIDIA cursor plane accepts only `ARGB8888` + `LINEAR`, and neither renderer can produce `LINEAR` for a dmabuf render target (measured: Vulkan 6 modifiers, GLES2 13, no LINEAR in either), so wlroots always falls back to compositing the cursor itself. The capture protocol reads `output->hardware_cursor`, which is then `NULL` — no positions at all. Fix: `~/src/wlroots-0.19.3-software-cursor-capture.patch` (15 lines, in `types/ext_image_capture_source_v1/output.c`) makes the cursor source fall back to the first visible entry in `output->cursors`. Built in `~/src/wlroots-0.19.3/build2` (release, byte-identical exported symbols) and installed over `/usr/local/lib/x86_64-linux-gnu/libwlroots-0.19.so`; unpatched backup at `~/src/libwlroots-0.19.so.unpatched-2026-09-06`. **Re-apply after any wlroots rebuild** or cursor tracking silently dies (`demovid doctor` catches it). `WLR_NO_HARDWARE_CURSORS` has been removed from BOTH `sway-nvidia` AND `~/.config/environment.d/nvidia-wayland.conf` — and note the systemd user manager caches env across gdm restarts, so `systemctl --user unset-environment` + `daemon-reload` is needed as well as the file edit.
- **`wf-recorder` here is a patched 0.5.0 in `/usr/local/bin`, which shadows the distro 0.4.1 in `/usr/bin`.** Upstream always overlays the cursor; the 4-line `--no-cursor` patch (source kept at `~/src/wf-recorder-0.5.0`, `ninja -C build install`) suppresses that second copy — worth it because `overlay_cursor=1` also calls `wlr_output_lock_software_cursors`, and `rec` passes the flag automatically when tracking is live. `demovid doctor` reports whether the flag exists, so an apt upgrade that shadows or replaces the build shows up there rather than as a mystery double cursor.
- **The cursor picture comes from the xcursor theme, not the protocol.** With a software cursor there is no cursor swapchain, so the capture session advertises a `0x0` buffer and no format — the image can never arrive that way. `demovid/rec/xcursor.py` reads the theme files directly and identifies the current shape by its HOTSPOT, which the protocol does give and which is near-unique per shape (Adwaita: arrow 3,1 / hand 7,5 / text 11,12). Ties go to the commoner shape (`context-menu` also sits at 3,1), and the largest art available is saved (96 px), so an enlarged cursor is drawn from real pixels. Positions arrive per output commit: ~48/s while moving, nothing while still.
- **The cursor is software-composited** → it is in every screencopy frame regardless of `overlay_cursor` (`--no-cursor` only drops wf-recorder's own second copy), and the portal's "hidden" mode can't remove it. The renderer therefore COVERS it: the same shape drawn enlarged about the same hotspot hides the 24 px original (verified on a real recording, 2026-09-06). A runtime `swaymsg seat * xcursor_theme demovid-blank 24` swap did blank it over a Brave window in a 0.6 s grim test (2026-09-04), but Wayland clients set their own cursor image and may bring it back on shape changes, and a blanked cursor also blinds the person demoing — so `rec` keeps the cursor by default (`--hide-cursor` opts in; the manifest records `cursor.hidden_during_rec`) and the renderer covers the 24 px real cursor with the synthetic one. Current theme: `Adwaita 24`.
- **No global pointer position from Wayland.** Route (1) `ext-image-copy-capture` pointer-cursor session is implemented and proven exact (warp-to-target error 0,0 px; hotspot 3,1 for Adwaita `left_ptr` 24 px, matching the theme file) — but only in a nested Sway, because the live session disables hardware cursors (above). Fallbacks if that stalls: (2) libinput/evdev deltas re-anchored by a transparent layer-shell surface's `wl_pointer.enter` (framepipe's `gayland` technique — GPL-3, copy the idea only); (3) pure evdev dead-reckoning (what Screenix does; drifts — needs `accel_profile flat`, a centre warp at start, and still breaks). Clicks and keys are trivially reliable via evdev either way: `amar` is in `input`, mouse = `/dev/input/event2`.
- **NVIDIA encode works through ffmpeg NVENC**; `wf-recorder -c h264_nvenc -p preset=p4 -p rc=vbr -p cq=20 -r 60 -f out.mp4` is the verified capture command (1080p60 clean). No VAAPI here (`wl-screenrec` is useless), `av1_nvenc` is listed but the 1060 has no AV1 encoder. gpu-screen-recorder (KMS capture + CUDA/NVENC) is the upgrade if screencopy drops frames — not packaged for Ubuntu 24.04, flatpak/source only.
- **xdg-desktop-portal-wlr rejects cursor mode METADATA** → PipeWire/portal streams can never be the position source on wlroots.
- Single output `HDMI-A-1` 1920×1080@144, scale 1. Webcam = Logitech C615 `/dev/video0` (720p/1080p). Default mic = the C615's mono capture. It sat at **53 % (hardware gain 6/18, +15 dB)** until 2026-09-03 — most of the "too quiet" complaint; now **85 % (hw 15/18, +28.5 dB)**, calibrated on his voice 2026-09-03 (peaks ≈ −6 dBFS, raw ≈ −27 LUFS — `loudnorm` at render does the rest), persisted by WirePlumber in `~/.local/state/wireplumber/default-routes`; if it drifts back down suspect a browser WebRTC AGC (`--disable-features=WebRtcAllowInputVolumeAdjustment` for Brave). Render still applies `loudnorm`.
- **YouTube upload runs on GCP project `yousef-amar` (created 2025-03-22)** via gog's desktop OAuth client (`~/.config/gogcli/credentials.json`, reused read-only; a `~/.config/demovid/client_secret.json` overrides it). Token: `~/.config/demovid/youtube_token.json`, scope `auth/youtube` (gog's own token is `youtube.readonly` — useless for insert). Google's stated policy (API revision history, 2020-07-28): `videos.insert` from unaudited projects created after that date is "restricted to private viewing mode" until the YouTube API Services compliance audit passes — this project qualifies, but Yousef has uploaded unlisted via the API before, so enforcement is unverified here; `demovid upload` compares the returned `privacyStatus` with the requested one and exits 3 on a mismatch, which is the test. Quota: 10,000 units/day, an insert costs 1,600 → ~6 uploads/day.
- Sway IPC is a superpower the Mac tools lack: `window` focus events + `get_tree` give exact window rects → zoom-to-focused-window, not a blind box around the pointer. Gotchas: i3ipc's `Con.leaves()` skips `floating_con`s — use `descendants()`; `SWAYSOCK` in an agent shell is often stale, `demovid.rec.sway.find_socket()` globs the live one; `for_window [pid=N] …` works as a runtime command and is how `rec` floats the preview before it can be tiled.
- **A DPMS-blanked output cannot be captured at all** (found 2026-09-06). `swayidle` here runs `output * power off` after 600 s; with the monitor asleep there is no committed buffer, so `grim` and `wf-recorder` fail with exactly the same "failed to copy output HDMI-A-1" as the explicit-sync fence leak — check `swaymsg -t get_outputs | jq '.[].power'` BEFORE blaming the renderer. `rec` calls `sway.wake_output()` first, and `doctor` reports a powered-off output as a WARN rather than a screencopy FAIL.
- **Sway 1.12 / wlroots 0.20 is NOT worth it here** (checked 2026-09-06 against the real 0.20.0 tarball): it wants `libdrm >= 2.4.129` (apt 24.04 has 2.4.125) and `xkbcommon >= 1.8.0` (apt has 1.6.0). Both have meson `fallback:` wraps, so it *would* build, but installing to `/usr/local` shadows the xkbcommon that sway, waybar and Brave all link — a session-wide risk. Toplevel capture would only add capture-time region recording; `render --crop/--window` already gives region output from the full-screen recording, and re-framing later is the better fit for record-raw-render-later. Revisit when Ubuntu ships the newer libs.
- **Preview/GUI on this box**: `mpv` is NOT installed (only a shell alias), ffmpeg's `sdl2` output creates a window Sway never maps (Xwayland/EGL on NVIDIA), so the webcam preview is `ffmpeg → rawvideo pipe → gst-launch-1.0 fdsrc ! rawvideoparse ! videoconvert ! waylandsink` (app_id is always `gst-launch-1.0`, match by pid). `libgtk-layer-shell.so.0` exists without a GI typelib — `tests/syncprobe/clockwindow.py` drives it via ctypes for an always-on-top overlay.
- **keyd grabs every keyboard** (`/etc/keyd/default.conf` ids `*`): physical nodes are silent, remapped keys come from `keyd virtual keyboard`. `rec` reads every key/button-capable evdev node (EVIOCSCLOCKID → monotonic timestamps), so each press is logged exactly once, tagged with `dev`.
- **Stream clocks (measured 2026-09-04, `tests/syncprobe/`)**: wf-recorder's first frame ≈ arrival of its stdout `Using video filter` line − 1.5 ms; v4l2 pts are CLOCK_MONOTONIC (`start:` in ffmpeg's input dump); pulse pts are wall clock minus reported latency but early packets arrive late, so the mic start is the median of per-packet implied starts 0.5–2.5 s after spawn (`ashowinfo`, `-copyts`). Results: screen capture times consistent to 6 ms (p5–p95) across 3517 frames; mic clicks repeatable to 1.8 ms with ~83 ms total playback-path latency that the HDMI sink's quantum 2048 + ALSA buffer accounts for; cam within ~1 frame at 30 fps (weak room-light signal). The C615 mic emits ~150 ms of garbage when woken from SUSPENDED → `rec` unsuspends it ≥ 0.4 s before capture. SIGINT streams *together* — sequential stop made the mic run 0.5 s long.

## Conventions
- **Idle speed-up** (`render --idle-speed N`): `render/timing.py` is pure — `idle_intervals()` finds stretches with no input (a cursor sample only counts as input if the pointer MOVED ≥2 px; Screenix logs positions while still) and, unless `--idle-ignore-speech`, no speech; `TimeMap` is the piecewise-linear source↔output clock that the render loop, the audio `aselect` and the caption timings all read, so they cannot drift apart. Speech detection is `media.silences()`: per-100 ms RMS via `asetnsamples` + `astats` (NB `astats`' `reset=` counts FRAMES, not samples — without `asetnsamples` you get one window for the whole file), then `speech_threshold()` = noise-floor mode + 6 dB. A fixed dBFS threshold does not work: this mic sits at ≈ −29 dBFS speech / ≈ −36 dBFS room, so `silencedetect=noise=-35dB` finds nothing.
- **Captions** (`render --captions`): `render/captions.py` posts `mic.flac` (transcoded to 16 kHz mono mp3, whisper's limit is 25 MB ≈ 70 min) to whisper-1 with `OPENAI_API_KEY`, caches segments in `<dir>/captions.json` keyed on the flac's size+mtime (re-renders are free), writes an `.srt` beside the mp4 in OUTPUT time, and burns it in with libass. **libass lays SRT out on a 384×288 PlayRes and scales**, so `force_style` sizes/margins are in those units, not output pixels — that is why the first attempt came out double size. Side margins clear a fixed-corner PiP automatically.
- **Background frame** (`render --pad/--bg/--radius/--no-shadow`): the compositor grew a `content` rect; with `pad > 0` the screen is inset on a solid/gradient/image background with rounded corners and a drop shadow, and everything (cursor, ripples, PiP) maps through `self.scale` + the content origin rather than `out_scale`.
- **Presets** (`render --preset NAME`, `--list-presets`): built-ins in `render/presets.py`, user overrides in `~/.config/demovid/presets.toml`. A preset only sets options the user did not type — `explicit_dests()` reads `sys.argv`, because comparing to the argparse default cannot tell `--idle-speed 0` from an absent flag. **Presets must never change the frozen taste defaults** (`--zoom`, `--zoom-hold`, `--pip-mode`, `--cursor-style`) until Yousef takes roadmap decision 8.
- **Region output** (`render --crop X,Y,W,H` / `--window NAME`): crops the source, shifts every event and the `preview_rect` into that frame (pointer events outside are dropped) and plans zoom inside it. No capture-time region recording (see the Sway 1.12 note above).
- **Console island**: `demovid/island.py` writes `~/.config/console/canvas/islands/demovid.{html,json}` (recent recordings + renders + upload links); `render` and `upload` refresh it on success, `python -m demovid.island` does it by hand. The hub live-reloads on write.
- **Waybar**: `scripts/waybar-demovid` (plain sh + jq, ~1 ms) reads the state file directly instead of spawning Python every second (~79 ms), and `rec` sends `SIGRTMIN+9` on start/stop for an instant update. The module in `~/.config/waybar/config` points at the script in the MAIN checkout, so it keeps working when a worktree is deleted.
- **Render overlays** live in `render/cursor.py` (`CursorTrack` positions, `ShapeTrack` + `draw_shape` for compositor-captured cursor images, synthetic arrow fallback) and `render/chips.py` (keystroke pills, PIL text on DejaVu Sans Bold — the only local font with ⌘ ⇧ ⌫ ⏎). `--synthetic-cursor` forces the stylised arrow; `--no-chips` / `--all-keys` / `--chip-hold` tune chips. Real-shape rendering is testable without a recording: `tests/xcursor.py` reads theme cursor files into the same BGRA the protocol delivers.
- **`FORMAT.md` is the contract** between `rec`, `import-screenix` and `render` (manifest.json + events.jsonl v1). Change it there first; `render` must keep reading every version ever written.
- **Subcommands are packages** `demovid/<name>/__init__.py` exposing `add_args(parser)` + `main(ns) -> int`; `cli.py` discovers them from `SUBCOMMANDS` and is never edited by feature work. Heavy imports (cv2, av, pywayland) stay inside `main()`. `uv sync --group dev`, `uv run demovid …`, `uv run pytest`.
- **Python 3.12 + `uv`** (decided 2026-09-03): `evdev`, `i3ipc`, `pywayland`, `numpy`/`opencv-python-headless`, `av`. ffmpeg/wf-recorder/pw-record are subprocesses, never re-implemented. **MIT** licence — framepipe is GPL-3, read it, never copy it.
- The zoom planner is a pure function `events → keyframes`; keep it that way and unit-test it. The renderer consumes keyframes, never raw events.
- **Render pipeline** (`demovid/render/`): `planner.py` (events → `{t,cx,cy,zoom}` keyframes, smoothstep between them, centre clamped per frame in `state_at`), `cursor.py` (zero-lag Gaussian-smoothed track, cached supersampled arrow sprites, click ripple), `compositor.py` (one `cv2.warpAffine` per frame for sub-pixel zoom/pan, then cursor, then PiP), `media.py` (ffmpeg rawvideo pipes: `Prefetcher` decode thread + `AsyncEncoder` write thread — the serial version ran at 28 fps, threaded 70 fps at 1080p60 on this 4-core Xeon; NVENC `-cq 20`; audio = two-pass `loudnorm` to −14 LUFS with `afftdn` in front, applied inside the encode ffmpeg so there is no intermediate). Iterate with `render --preview` (½ size, 30 fps, ~2× realtime) and `render --still <t>` (PNG at one instant — the frame-step tool); `--plan-json` dumps the keyframes. Cursor is drawn macOS-style (`--cursor-style dark`) because that is the Screen Studio look; `light` is Adwaita-like.
- Screenix import: `~/Videos/screenix/recording_<ts>/` has `cursor.json` (`{timestamp,x,y}` px @~120 Hz), `*.mp4.meta.json` (click events normalised 0–1 + key events), screen mp4 (with the mic audio inside) + `camera.seekable.mp4` — a free regression corpus; keep `demovid import-screenix` working. Imported dirs live at `~/Videos/demovid/2026-09-03-16-23-07/` (the 11.5-min Astera demo, 322 clicks) and two ~3 s smoke tests (`…16-10-48`, `…16-11-24`); streams are hardlinks, so they cost no disk.
- **Rec pipeline** (`demovid/rec/`): `demovid rec` toggles — idle → spawns `demovid rec --daemon` (state in `$XDG_RUNTIME_DIR/demovid/rec.json`, log in `rec.log`), live → SIGINT it. `session.py` orchestrates; `streams.py` = wf-recorder / ffmpeg-v4l2 / ffmpeg-pulse subprocesses (PR_SET_PDEATHSIG so a crashed daemon still finalises files) + the gst preview; `inputs.py` evdev; `sway.py` IPC focus/window log + output geometry; `cursor.py` the pywayland pointer-cursor session (bundled `pywayland.protocol.ext_image_copy_capture_v1`; raises on Sway 1.10 → `cursor_source: none`). `demovid doctor` checks prerequisites, `--restore` kills stray children / restores the cursor theme / clears state. Installed for the Sway keybind with `uv tool install -e ~/proj/code/demovid` → `~/.local/bin/demovid` (Sway's PATH lacks `~/.local/bin`, configs use the absolute path). Keys are logged by default (`--no-keys` for password-typing sessions).
- Never test against Yousef's live session in a way that mutates it. Recording his screen for a few seconds to `/tmp` is fine; changing seat/input settings must always be paired with a restore, and a crashed `rec` must leave a `demovid doctor --restore` path (cursor theme, mic gain, accel profile).
- Verify by artefact, not by claim: `ffprobe` the outputs (codec, fps, frame count), diff `events.jsonl` timestamps against the clip, frame-step a click in the render.
